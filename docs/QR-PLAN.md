## Offline-cache names (no clash with MMSA)

| MMSA | QR |
|---|---|
| `mm-app-<APP_VERSION>` | `qr-app-<APP_VERSION>` |
| `mm-qf-fonts-v1` | `qr-qf-fonts-v1` |
| `mm-ext-v1` | `qr-ext-v1` |
| `mm-mushaf-v1` | `qr-mushaf-v1` |

The old-cache clean-up in `app/sw.js` must only delete `qr-` caches. `tools/qr-verify/naming.mjs` checks this.
Storage keys such as `mm_disable_service_worker` stay as they are: storage belongs to one site address, so they
cannot clash, and keeping them keeps the shared scripts identical with MMSA.

## One worker for all of QR (QR J02 S3, not released)

- `app/sw.js` is a MODULE worker at `/app/sw.js`, scope `/app/`, for every QR page. Asma's `qr-sw-register.js` and
  MMSA's unchanged `sw-register.js` (the copied pages) ask for exactly the same script and type, so there is one
  registration and nothing flips between copies (`one-worker-browser.mjs`, both orders, 13 pages). The version comes
  from `app/js/qr-version.js`, imported (a new number is a change the browser sees). Version 00.17.
- It reproduces MMSA 077b4db's worker under QR names: `qr-app-<v>` (saved at install, carried forward to the next
  version, other app and data files kept on use with a background refresh), `qr-qf-fonts-v1`, `qr-ext-v1`
  (Firebase SDK), `qr-mushaf-v1`, plus Asma's `qr-quran-v1`. Asma's list, update note, Reload, kill switches and
  "Save for offline" are unchanged.
- Install: Asma's 52 files (1.68 MB) + the shell of the copied pages, 162 files (4.43 MB; the `SHELL` block in `app/sw.js`,
  generated by `tools/qr-sw/make-precache.mjs`, `--check` in npm test): 214 files, 6.1 MB. The Qur'an data (57 MB) and
  hadith data (37 MB) are kept only as they are opened.
- `tools/qr-verify/qr-offline-browser.mjs`: Quran Study and LDOG truly offline (signed in through MMSA's harness; it
  needs `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` so the harness's fakes reach the worker's own fetches).

- **The upgrade from the first Asma release (J02 S3b).** A phone with 76d3736's classic worker (`./sw.js?v=00.03`)
  keeps running its cached page, whose register asks for `./sw.js?v=<new>` as a CLASSIC worker. S3's `sw.js` used
  `import` statements, so it could not start that way and such a phone stayed on 00.03 for good (measured by
  `tools/qr-verify/upgrade-browser.mjs`). Now `sw.js` has no imports (the version and shell list are written into it
  by `make-precache.mjs`) and runs as classic or module. The phone sees one "new version" note; after Reload the new
  pages ask for `/app/sw.js` as a module, and because the worker running is the SAME version (started as
  `sw.js?v=<version>`), that second worker refuses to install. A refused install never reaches "installed", so no page
  shows a second note (an earlier try, taking over silently with `skipWaiting()`, still let MMSA's `sw-register.js`
  see "installed" and show "Updated — tap to reload" when the reader closed the tab and came back later). The
  registration stays on `sw.js?v=<version>` (the same code) until the next version, whose normal install moves it to
  `/app/sw.js` as a module; until then each page load fetches `sw.js` once and the refused install costs nothing else.
  `upgrade-browser.mjs` counts both notes (Asma's and MMSA's) on three paths at 390 and 1400: Reload then Asma;
  Reload then straight to Quran Study; tab closed without Reload, Quran Study opened later. One note each.
  Ticks, settings, the description choice and `qr-quran-v1` (the 51 surahs) survive; `qr-app-00.03` is deleted.
- **Which browsers run module service workers** (`register(…, { type: "module" })`), as far as I know (check caniuse
  "Module service workers" before relying on a version): Chrome and Edge from 91 (2021), Samsung Internet and other
  Chromium browsers of that age, Safari on macOS and iOS from 15 (2021). Firefox added them much later; I am NOT sure
  of the exact version (I believe it is a 2025–2026 release).
- **A browser without them:** QR's own register (Asma's pages) falls back to registering the same `/app/sw.js` as a
  classic worker, which it now can run (tested by `upgrade-browser.mjs` with module registration made to fail), so
  Asma still works offline. MMSA's register on the copied pages asks only for a module, fails quietly and changes
  nothing; those pages are then served by the classic worker if Asma registered one, and otherwise simply work online.
  A browser with no service workers at all gets every page online, as before.

## Offline (QR J01 R2): the Asma app

- **Worker:** `app/sw.js`, QR's own (not MMSA's copy), a CLASSIC worker so every browser with service workers runs it.
  Only `app/asma.html` registers it, through `app/js/qr-sw-register.js`, as `./sw.js?v=<APP_VERSION>`, scope `/app/`.
- **Version:** `app/js/qr-version.js` (`APP_VERSION`, QR numbering, allocated by the QR Architect; starts at `00.01`).
  The worker reads it from its own address. The page asks the network first for `qr-version.js`, so an online visit
  always learns of a new number.
- **Caches:**

  | Cache | What | Size | When |
  |---|---|---|---|
  | `qr-app-<APP_VERSION>` | the page, its 28 scripts, 2 stylesheets, 8 fonts, poster frame, manifest, icons, `asma-cited-hadith.json` (46 files) | 1.6 MB | saved when the worker installs |
  | `qr-quran-v1` | the 51 surah files the Names cite | 19.4 MB | each on first use, or all at once by the reader's "Save all āyāt for offline use (19 MB)" (progress shown) |

  Why not precache the surahs: 19 MB taken unasked on a first visit over a phone's data is unkind, and a large install
  fails more often. The Names, posters, groups and hadith work offline from the first visit; the āyāt a reader has
  opened are kept; one tap keeps them all. `qr-quran-v1` survives version changes, so a new version never downloads
  the 19 MB again.
- **Activate:** deletes every `qr-app-` cache except the current one, and nothing else (not `qr-quran-v1`, never `mm-`).
- **Updates:** a new worker WAITS. The page shows "A new version is ready · Reload"; only that tap swaps it in and
  reloads, back to the same view. Code never changes under a reader mid-visit.
- **Kill switches (as MMSA):** `?nosw` in the address, or `localStorage.mm_disable_service_worker = "1"`: the worker is
  unregistered and not registered again. `pages-browser.mjs` and `asma-browser.mjs` set the second;
  `asma-offline-browser.mjs` does not.
